# 字数统计示例

这一页的正文里有几行 `:::word-count`，所以指令所在的位置多出一块统计。不写范围时是**这一页所在
内容根**的数；后面写 `page` / `folder` / `site` 分别换成**本页**、**本文件夹（含子目录）**、
**全站**。数是构建时按整站算好的，正文其余部分一个字都不动 —— 标题、目录、翻页都在原来的位置。

每一块都先写一句合计，再摆一张明细表：文件、草稿、frontmatter、各级标题、代码、图表、表格、
链接、引用，末尾是词数、两类文字与字符数。四个范围摆的是同一张表，只是各自挑自己那一格。

:::word-count

## 数的是哪些文件

站点里有两份 docs 实例（`packages/` 与 `themes/` 那两棵内容根），各自那份清单加载到什么，这里
就数什么；这一页属于 `packages/` 那一份（实例 id 是 `default`），`/themes/` 那一页属于另一份
（实例 id 是 `themes`）。

草稿也数：生产构建把 `draft: true` 的那几份分到另一列，这里两列都读，所以草稿同样进各项合计，
明细里另有一行「草稿数量」。判据、代价与已知的口径都记在 `packages/theme-word-count/README.md`
（站点文档源只收 `docs/`，链接到包根那份只会是死链）。

## 换个范围

范围写在指令后面。下面三块按从小到大排：

### 本页

只数这一页自己的正文：

:::word-count page

### 本文件夹

这一页在 `theme-word-count/docs/` 里，这一块数的是那个目录下的所有页，子目录里的也算：

:::word-count folder

### 全站

两棵内容根（`default` 与 `themes`）的合计：

:::word-count site

## 数的是哪些字

正文按 MDX 解析成语法树后再数，数的位置是看得见的文字：段落、标题、表格里的格子、行内代码，
以及代码围栏里的源码。链接地址、图片的替代文字、JSX 属性与 `import` 行都不是「正文里读出来的
字」，一个都不数。markdown 与 MDX 的语法符号（`#`、表格的竖线、反引号、围栏那一行）同样不算。

四格缩进的代码块 MDX 本来就不认（站点那边也把它当普通文字），所以那几行按正文数，不进代码段；
指令本身是看不见的语法，不数。
