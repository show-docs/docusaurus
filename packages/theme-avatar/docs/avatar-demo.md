# 导航栏用户头像示例

看这一页的**右上角**：亮暗切换那颗按钮右边，本站什么也没有。

这不是这一层坏了。本站把它装进了 `plugins`（所以它的 `src/` 与主题层每构建一次就真编译一次），
但**故意不给 `userApi`** 那一格 —— 那一格是这一层的开关，指向的是站点自己的用户信息接口，
本包猜不出地址，也就不能给一个「看着像」的缺省。没有接口，就没有可问的对象，头像不出现，
亮暗切换照旧可用。

## 接上自己的接口之后会看到什么

站点在插件选项里写上 `userApi` 之后，同一位置会出现一张 24 px 的圆形头像；鼠标指上去展开下拉，
里面最多两行：

| 那一行   | 出现条件                    | 内容                                                  |
| -------- | --------------------------- | ----------------------------------------------------- |
| 个人中心 | 站点写了 `menu.profileHref` | `menu.profileLabelPrefix` 接上接口里的名字            |
| 退出登录 | 站点写了 `menu.logoutHref`  | `menu.logoutText` 那一串，按 `menu.logoutTarget` 打开 |

两行都不出现条件时，那里就只剩一张图，不再有下拉。

## 看不到头像的三种情况

- 站点没写 `userApi`（**本站就是这一种**）：整层不启用。
- 接口返回里没有 `fields.id` 那一格，或它是空值：当成没登录，不画。
- 接口给了头像地址之外的形状（例如 `avatar` 那格是数字），且站点没写 `defaultAvatar`：没有可画的图。

`enableHostname` 写给定时还有第四种：此刻地址栏的 hostname 与它不一致，整层不画。

## 这一页为什么值得留着

它是这一层在仓库里唯一的真实构建现场：`@theme-init/ColorModeToggle` 那条官方别名解析得到吗、
未编译的 `.tsx` 由站点编译时 babel 认不认、`usePluginData` 取到的那一格是不是配置期校验过的
那一份 —— 这三种坏法在「没装进站点」的包里都要等别人装上去才第一次炸。本站用一条不命中本站的
配置换来「构建跑到、渲染不出现」这一格，把它钉在 `test/plugin.test.mts` 那条真实构建里。

选项的每一格、缺省与「为什么这些格没有缺省值」在那一份使用说明里：
[导航栏用户头像的 README](../README.md)；实现侧的取舍记在
[`docs/internals.md`](./internals.md)。
