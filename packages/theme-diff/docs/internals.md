# theme-diff 维护者文档

这份写的是**改这个包之前要知道的事**：内部组成、`git` 那几步怎么调、取不到差异时的几种落点、
以及这份数据被 webpack 缓存到哪一格。使用者要看的（怎么触发、对比的是哪份文件、有哪些局限）
在 [`README.md`](../README.md)，这里不重复。

## 组成

| 文件                            | 编译吗              | 职责                                                                                                                                                                              |
| ------------------------------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/index.mts`                 | ✅ `src/` → `dist/` | 入口：查两条安装前提（theme-iframe 与 component-page）、在 `loadContent()` 里交出 `diff` 那一页、给出层目录、把那条 `enforce: 'post'` loader 挂到 `.md` 上、交出样式表            |
| `src/component-pages.mts`       | ✅ `src/` → `dist/` | 本层交出的那一列条目：一把 `diff` 键、判法 `any`（`true` / 路径 / `{ old, new }` 都算命中）、组件写 `@theme/DiffPage`                                                             |
| `src/loader/diff-decision.mts`  | ✅                  | 纯函数三把：frontmatter 里 `diff:` 那把键的读法（`true` / 路径 / 引号 / `false`，值折到下面几行时把续行收回来）、值是**一份文件还是 `{old:, new:}` / 块式那两条**、目标路径怎么解 |
| `src/loader/git-diff.mts`       | ✅                  | `git` 调用：找仓库根、问仓库相对路径、取「上一个版本 → 此刻这一份」的 diff 与左边那一份内容；另有一次 `diff --no-index`，比磁盘上的两份文件                                       |
| `src/loader/md-diff-loader.mts` | ✅                  | `enforce: 'post'` 那一步：从磁盘上的源文件读判据，按两种来源算出差异，追加成一条 `export const diff`                                                                              |
| `src/types.mts`                 | ✅（只出类型）      | `DiffData`（追加的那条导出的形状，带 `source` 与 `caption`）与 `LoaderContextExtras`                                                                                              |

| `components/diff-view.tsx`      | ❌ 站点编译         | 浏览器侧：把 `git diff` 原文交给 `@git-diff-view/react`，配色跟站点的亮暗模式，说明行按 `source` 给两种说法                                                                       |

## `git` 调用：两种来源

全在构建期，用 `execFileSync('git', 参数数组, { cwd })`：路径里有空格或引号时拼命令串会被
shell 拆开，`git log` 那一步还会把别人的路径当成参数。

### `diff: true` / 单份路径 —— 一份文件的上一个版本 → 此刻这一份

1. `rev-parse --show-toplevel`（在目标文件所在目录跑）—— 仓库根；跑不起来就是「不在仓库里」。
2. `rev-parse --show-prefix`（同样在目标文件所在目录跑）—— 这份文件在仓库里的相对路径里
   除了文件名那一段（仓库根上为空串）。文件名从本地路径取，git 打出来的一律是正斜杠。
   这一串同时是视图上方显示的那一个文件名。
3. `log --format=%H --follow -n 2 -- <仓库相对路径>` —— 动过这份文件的最后两个提交。
   一条都没有说明这份文件还没提交过：磁盘上这一份不在历史里，也没有 `HEAD` 里那一份可当上一个版本。
4. `diff -M HEAD -- <路径>` —— 这份文件在 `HEAD` 里的那一份比工作区。**有输出就用这一条**：
   右边是磁盘上此刻这一份，左边用 `show HEAD:<路径>` 取；`--name-status` 给 `A`（这份文件在
   `HEAD` 里还没有）时左边是空串。
5. 没有输出（工作区就是这份文件最后一次被提交的样子）时才往它自己的历史里比：
   `diff -M --follow <prev> HEAD -- <路径>` 拿差异，`--name-status` 那一步拿类型与旧名
   （重命名时旧名在那一条里），新增（`A`）没有旧版本可读，其余用 `show <prev>:<旧名>` 取左边
   那一份。到这一步少于两个提交就没有上一个版本可对比 —— 列表里最后一条就是唯一那一次时，
   它自己就是「此刻这一份」。

这里问 `HEAD` 不等于看整仓最近一次提交：`<路径>` 那份 pathspec 只圈住这份文件，`HEAD:<路径>`
就是它自己最后一次被改动时的内容；后面那些提交没动过它，那些提交在这条差异里就不存在。

两条都用 `-M` 认改名；`--follow` 只加在历史那一条上，工作区那一条不比历史，用不上它。
历史那一条的差异不会是空串（`git log` 只登记改动过它的那一次，两个提交都登记了，这两版就必然不同），
工作区那一条则要靠输出判空 —— 空就是干净，得往第 5 步去。

第 2 步是**向 git 问**出来的，不自己算。仓库根出自 git、文件地址出自 webpack，同一个目录在
Windows 上可以有两条写法：8.3 短名（`C:\Users\RUNNER~1\…`）不被普通 `fs.realpathSync` 展开，
而 git 恒展开成长名（`C:\Users\runneradmin\…`）。拿 `path.relative()` 逐段比这两种写法，第二个
段就分叉，算出来的是 `../../../../../RUNNER~1/…` 这种逃出仓库的地址，git 随即报
「outside repository」，这一页的差异视图静默变成一句告警。构建从短名目录起手（账号名带空格
被转成短名的机器、或检出落在短名临时目录里）会真撞上这一条，不只是测试夹具。

### `diff: {old: 旧, new: 新}` —— 磁盘上的两份文件

只有 `diff --no-index -- <旧> <新>` 一步，在**这份 md 所在目录**跑，两个地址按相对那个目录的
写法给。不读 git 历史，也不要求这两份在仓库里；git 的差别算法、`-M` 那类识别都不掺进来，
头部两个名字因此就是视图上方显示的那一行。`--no-index` 的退出码要说清：
有差别时它**退 1**，而 `execFileSync` 把非零退出当错误抛出，差异文本挂在 `error.stdout` 上；
两份一样时退 0、输出为空。所以「退 1」不能直接当成失败 —— `readFilesChange` 按输出区分，
只有拿到差异文本才认它是成功，`Could not access` 那种「退 1 但输出为空」照原样抛出，
由调用方按「git 出问题」那一种落点处理。

左右两格由**键名**定：`old` 交给 `--no-index` 的第一个地址、`new` 交给第二个，所以两条写在
frontmatter 里的先后不影响产物。`diff:` 那一行空着、把值折到下面几行时，`readDiffValue` 只收
缩进的后续行（顶格的下一把键或空行就停），`{ }` 折行与 `old:` / `new:` 各一行的块式写法都落到
`splitDiffValue`：流式按逗号分项、块式按行分项，每项再按第一个冒号分键与值。因此流式那两个地址
里不能带逗号（块式没有这条限制；带冒号没事，Windows 的盘符写法落在值里）—— 判据读的是
frontmatter 原文，跟 YAML 把它读成什么都不影响是两回事。

## 取不到差异时的几种落点

`md-diff-loader` 只有这几种结果，每一种都让这一页照常渲染正文：

| 情况                                                                      | 落点                                       |
| ------------------------------------------------------------------------- | ------------------------------------------ |
| frontmatter 没有 `diff:` 这把键                                           | 原样交回，什么都不追加，也不告警           |
| 写成两份对照（`{ }` 或块式）但凑不出正好 `old` 与 `new` 两个键            | 一条告警，带回原文那个值                   |
| 单份路径指向的文件在磁盘上不存在                                          | 一条告警（带解析出来的绝对路径）           |
| 两份里 `old` 或 `new` 那一份在磁盘上不存在                                | 一条告警，点名是哪一个键，带绝对路径       |
| 单份那种：不在 git 仓库里、这份文件还没提交过、或提交过一次之后没有再改动 | 一条告警，说清是「没有可对比的上一个版本」 |
| 两份那种：两份内容一模一样                                                | 一条告警，说「没有差别」                   |
| `git` 本身出问题（仓库损坏、`git` 不在 PATH、那两份里有一份读不到）       | 一条告警，带 `git` 那句消息                |

告警都走 `this.emitWarning()`：只让这一页少一块视图，不让整站构建失败。
`LoaderContextExtras` 补的就是 `emitWarning` 这一件 —— webpack 跑 loader 时确实挂在上下文上，
但它对外发布的 `LoaderContext` 类型只拼了 loader-runner 那一半。

## 这份数据缓存到哪一格

差异是 loader 的产物，所以走 webpack 的模块缓存，输入只有这份 `.md` 自己：
「又提交了一次」不会让它重算，`diff: {old: 旧, new: 新}` 那两份文件改了内容也不会，改动这份 md
或清掉构建缓存才会。这一格写进了 README 的「已知限制」，改 loader 的入参时记得两边一起改。

## 厂商那份视图

`@git-diff-view/react` 的解析与展开都在 `DiffFile` 实例里做，换一份数据就重建、不做增量。
两处踩过的点：

- `setEnableFastDiffTemplate()` 是**全局**设置，且要在 `DiffFile.createInstance()` 之前设；
  放在 `useMemo` 里，重建实例前再设一遍没有代价。
- 展开与并排用 `onAllExpand('split')` 加 `DiffModeEnum.SplitGitHub`，视图写死在组件里，
  不做成选项。

## 用例与红线

- 构建期判据：`test/theme-diff.test.mts` —— 真 git 仓库（临时目录里真提交），
  `src/` 全份（`loader/` 那三份与入口那份）挂在覆盖率红线上（`vitest.config.mts` 的
  `coverage.include` 盖住每个包的 `src/`）。
  两份文件那条不建仓库，夹具直接放在仓库外的临时目录里，顺便钉住「这条来源不读 git 历史」。
- 页面上那块视图：`test/e2e/features/diff.feature`。**不**断言具体改了哪几行 ——
  单份那种来源里右边是磁盘上此刻这一份，这一页改一行、或下一笔提交都会变。对照那两条只认两份文件名与
  「有改动行」这一格。
- 共用外壳：三条视图层（本包、`theme-markmap`、`theme-erd`）的兜底、视图那一格、宽度补丁与页面组件的
  全部内容都只有一份实现，住在 `packages/theme-iframe/lib/view-layer-shell.tsx`，每个包只留
  「交哪把键、交哪个组件、交哪段说法」—— 三条都是清单挂上的页面（`DiffPage` / `MarkmapPage` /
  `ErdPage`，三页结构逐行相同）；
  `test/view-layer-copies.test.mts` 钉「三处引的是同一份」，`test/view-layer-shell.test.mts`
  量共享实现自己的分支，另钉两条 md loader 的 frontmatter 正则同口径、「键名 = 追加的导出名」。
